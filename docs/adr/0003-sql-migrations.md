# ADR-003: Plain SQL migrations and psycopg, no ORM

- Status: accepted
- Date: 2026-11-26

## Context

The schema is small (about a dozen tables), the queries are a mix of bulk upserts and analytics,
and LangGraph's Postgres checkpointer already uses psycopg 3.

## Decision

Use psycopg 3 (async, connection pool) with hand-written SQL. Schema changes are forward-only
`.sql` files in `common/migrations/`, applied in lexical order by `python -m common.migrate`, which
records each version in `schema_migrations`.

## Consequences

- One driver for app code and checkpoints; no ORM session semantics to learn or debug.
- No autogenerated down-migrations. Rolling back means writing a new forward migration.
